### 2.2 Literature Corpus Module (文献库管理)

**三层文献集成（带导师库分类）：**

```
Unified Literature Index
├── Layer 1: User-Uploaded (自上传)
│   ├── Original PDFs
│   ├── Extracted Text
│   └── Metadata
│
├── Layer 2: Advisor-Organized Corpus (导师库 - 分导师管理)
│   ├── Advisor A's Library
│   │   ├── Research Topic 1
│   │   ├── Research Topic 2
│   │   └── [Shared with authorized researchers]
│   ├── Advisor B's Library
│   │   ├── Policy Analysis
│   │   ├── Governance Studies
│   │   └── [Shared with authorized researchers]
│   ├── Advisor C's Library
│   │   └── [...]
│   └── [Access Control: 按研究者的导师关系决定可见性]
│
└── Layer 3: External Databases (外部数据库)
    ├── Web of Science
    ├── CNKI
    ├── Google Scholar
    └── arXiv
```

**导师库的关键特性：**
- 每个导师拥有独立的文献库
- 研究者可关联一个或多个导师，获得相应导师的库访问权限
- 跨导师的论文可以被标记为"共享"或"推荐"
- 支持子领域分类（每个导师库内部的组织）

### 2.3 Agent Orchestration Module (Agent编排)

**工作模式定义：**

```
Query Input
    │
    ├─→ Query Understanding (理解查询意图)
    │   - 提取关键概念
    │   - 判断查询类型（见下文）
    │   - 加载研究者上下文
    │
    ├─→ Task Routing (任务路由)
    │   ├─ Concept Positioning Mode (概念定位模式)
    │   ├─ Literature Review Mode (文献综述模式)
    │   ├─ Mechanism Analysis Mode (理论机制模式)
    │   ├─ Research Design Mode (研究设计模式)
    │   └─ Variable & Measurement Mode (变量测量模式)
    │
    ├─→ Retrieval & Evidence Gathering (检索与证据收集)
    │   - Vector search with researcher context
    │   - Filter by metadata tags
    │   - Rank by relevance to current task
    │
    ├─→ LLM Processing (LLM处理)
    │   - Multi-turn reasoning
    │   - Concept-to-location mapping
    │   - Research application inference
    │
    └─→ Output Formatting (输出格式化)
        - 概念位置 (Concept Location)
        - 研究用途 (Research Usage)
        - 进一步建议 (Further Suggestions)
```

**五种查询模式：**

| 模式 | 输入 | 核心过程 | 输出 |
|------|------|--------|------|
| **Concept Positioning** | 概念名称 | 查找定义、操作化、理论脉络 | 概念定义+文献位置+不同理解方式 |
| **Literature Survey** | 研究主题 | 聚类相关文献、理论发展脉络 | 文献地图+理论进展+空白识别 |
| **Mechanism Analysis** | 理论机制/假设 | 查找支持/反驳证据、对标设计 | 机制解释+实证支持+方法论建议 |
| **Research Design** | 研究问题 | 查找同类研究、变量设计、实证策略 | 研究框架+方法论参考+创新建议 |
| **Measurement** | 变量名称 | 查找测量方式、量表、操作化 | 测量方法+工具推荐+改进建议 |

## 5. 关键技术决策

### 5.1 Embeddings策略

```
对每篇论文，维护多个level的embedding：

Level 1: Full Text Embedding
- 用于宽泛检索
- 维度：1536 (OpenAI Ada v2)

Level 2: Section Embeddings
- 按 Introduction / Methodology / Results / Discussion
- 用于精准定位

Level 3: Concept Embeddings
- 围绕每个identified concept的小段落
- 收集 concept 的definition + context

Level 4: Researcher Context Embedding
- 当前研究者当前任务的context向量
- 用于personalization re-ranking
```

### 5.2 Concept Extraction Pipeline

```
Raw Paper
  │
  ├─→ 1. NER + Domain-specific extraction
  │   (识别概念、变量、方法等)
  │
  ├─→ 2. Entity linking
  │   (链接到已知概念)
  │
  ├─→ 3. Relation extraction
  │   (概念间关系：操作化、定义、支持、矛盾)
  │
  ├─→ 4. Location tagging
  │   (标记概念在文献中的位置与角色)
  │
  └─→ Structured Concept Graph
```

### 5.3 个性化排序 (Personalized Ranking)

```
检索得到 candidates 的初始排序后：

Score = w1 * Vector_Similarity 
       + w2 * Researcher_Relevance
       + w3 * Research_Stage_Relevance
       + w4 * Meta_Alignment
       + w5 * Recency
       + w6 * Reading_Pattern_Fit

其中：
- Vector_Similarity：查询与文献的向量相似度
- Researcher_Relevance：这个topic与研究者历史兴趣的关联度
- Research_Stage_Relevance：与当前研究阶段的匹配度
  (topic selection → empirical design → publication)
- Meta_Alignment：治理主体、政策工具等metadata匹配
- Recency：发表时间（可配置权重）
- Reading_Pattern_Fit：与研究者已读文献的相似性
```

### 5.4 导师库检索策略 (Advisor Library Search Strategy)

```
多维度导师库过滤与排序：

1. Access Control Filter (访问控制)
   目的：确保只检索有权限的导师库
   逻辑：
   - 获取研究者关联的所有导师 (researcher_advisors 表)
   - 只在这些导师的库中检索
   - 用户自上传的库始终可见

2. Library Source Priority (库源优先级)
   可配置的优先级排序：
   a) My Uploads (个人上传) - 通常权重最高
   b) Primary Advisor's Library (主导师库) - 权重高
   c) Co-Advisor/Mentor Libraries (辅导师库) - 权重中
   d) External Databases (外部库) - 可选

3. Sub-field Filtering (子领域过滤)
   - 每个导师库内支持多个子领域 (如 "governance", "policy_analysis")
   - 用户可选择跨领域搜索或限制在特定领域
   - 元数据中记录论文属于导师库中的哪个子领域

4. Library-aware Ranking
   最终排序分数调整：
   Score = w1 * Vector_Similarity 
         + w2 * Researcher_Relevance
         + w3 * Research_Stage_Relevance
         + w4 * Meta_Alignment
         + w5 * Recency
         + w6 * Reading_Pattern_Fit
         + w7 * Library_Source_Weight     ← NEW
         + w8 * Advisor_Recommendation_Score  ← 导师标记的重要文献

5. 推荐引擎
   - 导师在上传论文时可以添加tags: "核心文献", "方法参考", "争议讨论"
   - 系统优先推荐导师标记为"核心文献"的论文
   - 这些标记成为检索排序的重要信号
```

**Advisor Filter Query 示例：**
```python
# 按优先级搜索：只在指定导师的库中检索
search_result = retrieve(
    query_embedding=query_emb,
    filters={
        "source_priority": ["my_uploads", "primary_advisor", "co_advisor"],
        "advisor_ids": [advisor_1_uuid, advisor_2_uuid],
        "sub_fields": ["governance", "policy_tools"],  # 可选
        "library_tags": ["核心文献", "方法参考"],  # 导师标记
    },
    rerank_weights={
        "vector_sim": 0.20,
        "researcher_relevance": 0.15,
        "research_stage": 0.15,
        "library_source": 0.25,  # 导师库权重
        "advisor_tag": 0.20,
        "recency": 0.05
    }
)
```


## 7. 系统部署架构

```
Frontend (Web/Desktop)
    │
    ▼
API Gateway + Auth
    │
    ├─→ Query Service (Query parsing + Routing)
    ├─→ Retrieval Service (Search + Ranking)
    ├─→ LLM Service (Multi-LLM support)
    └─→ Profile Service (Researcher data)
    │
    ▼
Message Queue (Redis/RabbitMQ)
    │
    ├─→ Paper Processing Worker
    │   └─ PDF extraction, NER, indexing
    ├─→ Embedding Worker
    │   └─ Generate embeddings
    └─→ Feedback Processor
        └─ Update models/rankings
    │
    ▼
Data Layer
├─ PostgreSQL (structured data)
├─ Pinecone/Weaviate (vector search)
├─ MongoDB/OpenSearch (documents)
└─ Redis (cache)
```
