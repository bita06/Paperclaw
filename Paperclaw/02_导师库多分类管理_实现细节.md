# 导师库多分类管理 - 实现细节

## 1. 核心概念

### 1.1 多层级关系结构

```
System
├── Advisor (导师) - 账户owner
│   ├── Sub-field 1 (治理研究)
│   │   └── Papers (该领域的论文集合)
│   ├── Sub-field 2 (政策工具)
│   │   └── Papers
│   └── Sub-field N
│       └── Papers
│
├── Researcher (研究者) - 用户
│   └── Advisor Relationships
│       ├── Primary Advisor (主导师) - 1:1
│       ├── Co-Advisors (辅导师) - 1:M
│       └── Mentors (导师) - 1:M
│
└── Paper (论文)
    ├── Owner Library (所属库)
    │   ├── My Uploads (个人库)
    │   ├── Advisor X's Library (导师A库)
    │   ├── Advisor Y's Library (导师B库)
    │   └── External (外部)
    └── Visibility (可见性控制)
        ├── public (所有人)
        ├── advisor_only (仅导师)
        └── research_group_only (课题组)
```

## 2. 数据库设计详解

### 2.1 核心表关系图

```sql
-- 导师表：存储导师基本信息
TABLE advisors {
  id: UUID PK
  name: TEXT              -- 王教授
  affiliation: TEXT       -- 清华大学
  email: TEXT
  research_areas: TEXT[]  -- ['governance', 'policy']
  created_at: TIMESTAMP
}

-- 导师子领域表：每个导师可管理多个研究领域
TABLE advisor_sub_fields {
  id: UUID PK
  advisor_id: UUID FK → advisors(id)
  field_name: TEXT        -- "治理结构研究"
  description: TEXT       -- 字段描述
  display_order: INT      -- 显示顺序
  created_at: TIMESTAMP
  UNIQUE(advisor_id, field_name)
}

-- 研究者-导师关系表：记录谁是谁的学生/mentee
TABLE researcher_advisors {
  id: UUID PK
  researcher_id: UUID FK → researchers(id)
  advisor_id: UUID FK → advisors(id)
  relationship_type: VARCHAR  -- 'primary_advisor' | 'co_advisor' | 'mentor'
  access_level: VARCHAR       -- 'full' | 'readonly'
  joined_at: TIMESTAMP
  UNIQUE(researcher_id, advisor_id)
}

-- 导师库论文表：论文与导师库的关联
TABLE advisor_library_papers {
  id: UUID PK
  advisor_id: UUID FK → advisors(id)
  paper_id: UUID FK → papers(id)
  sub_field_id: UUID FK → advisor_sub_fields(id)
  library_tags: TEXT[]    -- ['核心文献', '方法参考', '争议讨论']
  added_by_advisor_at: TIMESTAMP  -- 添加时间
  added_by: UUID                  -- 添加者ID (导师或助手)
  notes: TEXT                     -- 导师的备注
  UNIQUE(advisor_id, paper_id)
}

-- 论文表：扩展metadata以支持多库源
TABLE papers {
  id: UUID PK
  title: TEXT
  authors: TEXT[]
  year: INT
  venue: TEXT
  doi: TEXT UNIQUE
  source: VARCHAR  -- 'uploaded' | 'advisor_library' | 'wos' | 'cnki' | 'arxiv'
  source_library_id: UUID  -- 如果来自导师库，record which advisor's library
  visibility: VARCHAR      -- 'public' | 'advisor_only' | 'research_group_only'
  indexed: BOOLEAN DEFAULT false
  created_at: TIMESTAMP
  updated_at: TIMESTAMP
}

-- 查询审计日志：记录用户的检索行为
TABLE search_audit {
  id: UUID PK
  researcher_id: UUID FK
  query_text: TEXT
  selected_advisors: UUID[]  -- 选择的导师库
  selected_sub_fields: TEXT[]
  results_count: INT
  clicked_paper_ids: UUID[]  -- 用户点击的结果
  created_at: TIMESTAMP
}
```

### 2.2 查询流程中的SQL示例

**场景：研究者查询"治理结构"，指定只查王教授和李教授的库**

```sql
-- Step 1: 验证访问权限
SELECT DISTINCT ra.advisor_id
FROM researcher_advisors ra
WHERE ra.researcher_id = $researcher_id
  AND ra.advisor_id IN ($advisor_1_uuid, $advisor_2_uuid)
  AND ra.access_level = 'full'

-- Step 2: 从指定导师库检索论文
SELECT p.id, p.title, p.doi, alp.library_tags, alp.notes,
       asf.field_name, alp.added_by_advisor_at
FROM papers p
JOIN advisor_library_papers alp ON p.id = alp.paper_id
JOIN advisor_sub_fields asf ON alp.sub_field_id = asf.id
WHERE alp.advisor_id IN ($advisor_1_uuid, $advisor_2_uuid)
  AND p.indexed = true
  AND (asf.field_name IN ($selected_fields) OR $selected_fields IS NULL)
ORDER BY 
  CASE 
    WHEN alp.advisor_id = $primary_advisor_id THEN 1
    ELSE 2
  END,
  CASE 
    WHEN 'core_paper' = ANY(alp.library_tags) THEN 1
    WHEN 'method_reference' = ANY(alp.library_tags) THEN 2
    ELSE 3
  END,
  alp.added_by_advisor_at DESC

-- Step 3: 也加入用户自己上传的论文
SELECT p.id, p.title, p.doi, NULL::TEXT[] as library_tags, NULL::TEXT as notes,
       '个人上传' as field_name, p.created_at as added_by_advisor_at
FROM papers p
WHERE p.source = 'uploaded'
  AND p.indexed = true
  -- 这些结果权重最高，会在排序时被提到前面
```

## 3. 检索与排序机制

### 3.1 Four-Stage Retrieval Pipeline

```
┌─────────────────────────────────────────────────┐
│ Stage 1: Access Control (访问控制)              │
│ ────────────────────────────────────────────────│
│ 获取研究者有权限的所有导师库                     │
│ Input: researcher_id, advisor_filters           │
│ Output: [advisor_1_uuid, advisor_2_uuid, ...]   │
└─────────────────┬───────────────────────────────┘
                  │
┌─────────────────┴───────────────────────────────┐
│ Stage 2: Vector Search (向量检索)               │
│ ────────────────────────────────────────────────│
│ 在permitted导师库中做向量相似度搜索             │
│ + 个人上传的论文                                 │
│ Input: query_embedding, advisor_ids, sub_fields│
│ Output: candidate_papers (top-K, ~100)         │
└─────────────────┬───────────────────────────────┘
                  │
┌─────────────────┴───────────────────────────────┐
│ Stage 3: Metadata Filtering (元数据过滤)        │
│ ────────────────────────────────────────────────│
│ 按论文标签、年份、方法等进一步过滤               │
│ Input: candidates, library_tags, year_range     │
│ Output: filtered_papers                         │
└─────────────────┬───────────────────────────────┘
                  │
┌─────────────────┴───────────────────────────────┐
│ Stage 4: Personalized Ranking (个性化排序)      │
│ ────────────────────────────────────────────────│
│ 融合多信号进行最终排序                           │
│          (见下一小节)                            │
│ Output: ranked_results (top-20)                 │
└─────────────────────────────────────────────────┘
```

### 3.2 排序信号详解

```python
# 最终排序分数计算

score = (
    w1 * vector_similarity +           # 0.20 向量相似度
    w2 * library_source_weight +       # 0.25 所属库权重
    w3 * advisor_tag_score +           # 0.20 导师标记分
    w4 * researcher_relevance +        # 0.15 研究者相关度
    w5 * research_stage_match +        # 0.12 研究阶段匹配
    w6 * recency_score +               # 0.05 時效性
    w7 * co_citation_score             # 0.03 共被引分
)

# 详细说明：

## w1: vector_similarity (0.20)
# 标准的BM25 / 向量相似度
# normalized_sim_score = (cos_similarity - min_sim) / (max_sim - min_sim)

## w2: library_source_weight (0.25) ← 导师库特有
# Source Priority Scoring:
library_weights = {
    "my_uploads": 1.0,              # 个人上传，权重最高
    "primary_advisor": 0.95,        # 主导师库
    "co_advisor": 0.80,             # 辅导师库
    "mentor": 0.70,                 # mentor库
    "external": 0.50                # 外部库
}
# 还可加权：是否在被选择的过滤条件中
# include_boost = 1.1 if in selected_advisors else 1.0

## w3: advisor_tag_score (0.20) ← 导师库特有
# 导师添加的标签对应的分数
advisor_tags = {
    "核心文献": 1.0,
    "方法参考": 0.8,
    "理论背景": 0.6,
    "争议讨论": 0.5,
    "工作论文": 0.3,
    None: 0.2
}
advisor_tag_score = advisor_tags.get(paper.tag, 0.2)

## w4: researcher_relevance (0.15)
# 基于研究者长期兴趣与当前论文的相关度
# 通过embedding距离计算
relevance_score = cosine_sim(
    researcher_profile_emb,
    paper_content_emb
)

## w5: research_stage_match (0.12)
# 根据当前研究阶段判断论文在这个阶段的相关性
stage_relevance = {
    ("topic_selection", "literature_review"): 1.0,
    ("literature_review", "literature_review"): 0.95,
    ("empirical_design", "methodology"): 0.9,
    ("writing", "discussion"): 0.7
}

## w6: recency_score (0.05)
# 时效性（可配置权重，有些研究需要最新文献）
# logarithmic decay based on publication year
years_ago = current_year - paper.year
recency_score = 1.0 / (1.0 + np.log(years_ago + 1))

## w7: co_citation_score (0.03)
# 与研究者已读文献的共被引关系
co_citation_count = count_papers(
    cited_by(paper) ∩ cited_by(researcher_read_papers)
)
co_citation_score = min(co_citation_count / 10, 1.0)
```

### 场景1：按导师库分类搜索

**系统处理：**

4. Return: 按导师标记 + 向量相似度重排输出

**用户查询：** "找'公共问题解决机制'，优先从我的上传和王老师库，但也可以看李老师和外部库"

**系统处理：**

4. Final Rank: 综合向量相似度和导师标记
5. Return: 个人上传 + 王教授核心文献 优先显示

## 5. 实现的代码框架伪代码

### 5.1 检索服务伪代码

```python
class AdvisorLibrarySearchService:
    
    def search(self, researcher_id: UUID, query: SearchQuery):
        """
        主检索入口
        """
        # Step 1: Access Control
        permitted_advisors = self.get_permitted_advisors(
            researcher_id, 
            query.advisor_filters.advisor_ids
        )
        
        # Step 2: Vector Search
        candidate_papers = self.vector_search(
            query_embedding=self.encode(query.query_text),
            advisor_ids=permitted_advisors,
            sub_fields=query.advisor_filters.sub_fields,
            top_k=100  # 检索更多候选
        )
        
        # Step 3: Metadata Filtering
        filtered_papers = self.filter_by_metadata(
            candidate_papers,
            library_tags=query.advisor_filters.library_tags,
            pub_year_range=query.year_range,
            source_priority=query.source_priority
        )
        
        # Step 4: Personalized Ranking
        ranked_papers = self.rank_with_signals(
            filtered_papers,
            researcher_id=researcher_id,
            weights={
                'vector_sim': 0.20,
                'library_source': 0.25,
                'advisor_tag': 0.20,
                'researcher_relevance': 0.15,
                'research_stage': 0.12,
                'recency': 0.05,
                'co_citation': 0.03
            }
        )
        
        # Step 5: Return Top-K
        return ranked_papers[:20]
    
    def get_permitted_advisors(self, researcher_id, requested_advisors):
        """
        返回研究者可访问的导师库
        """
        advisors = db.query(
            f"""
            SELECT DISTINCT ra.advisor_id
            FROM researcher_advisors ra
            WHERE ra.researcher_id = {researcher_id}
              AND ra.access_level = 'full'
            """
        )
        
        # 如果用户指定了具体的导师，做交集
        if requested_advisors:
            advisors = list(set(advisors) & set(requested_advisors))
        
        return advisors
    
    def rank_with_signals(self, papers, researcher_id, weights):
        """
        多信号融合排序
        """
        ranked = []
        
        for paper in papers:
            score = (
                weights['vector_sim'] * paper.vector_sim_score +
                weights['library_source'] * self.get_library_source_weight(
                    paper.source, paper.advisor_id, researcher_id
                ) +
                weights['advisor_tag'] * self.get_advisor_tag_score(
                    paper.library_tags
                ) +
                weights['researcher_relevance'] * self.get_researcher_relevance(
                    paper, researcher_id
                ) +
                weights['research_stage'] * self.get_research_stage_match(
                    paper, researcher_id
                ) +
                weights['recency'] * self.get_recency_score(paper) +
                weights['co_citation'] * self.get_co_citation_score(
                    paper, researcher_id
                )
            )
            
            ranked.append((paper, score))
        
        # 按分数降序排列
        ranked.sort(key=lambda x: x[1], reverse=True)
        
        return [p for p, _ in ranked]
```

## 6. 导师库管理接口

### 6.1 导师侧：库管理

```
POST /api/advisors/{advisor_id}/sub-fields
- 创建新的研究领域分类

POST /api/advisors/{advisor_id}/library/papers
- 添加论文到导师库
- 参数：paper_id, sub_field_id, library_tags[], notes

PUT /api/advisors/{advisor_id}/library/papers/{paper_id}
- 更新论文的标签和备注

DELETE /api/advisors/{advisor_id}/library/papers/{paper_id}
- 从导师库移除论文
```

```
GET /api/researchers/{researcher_id}/accessible-advisors

GET /api/papers/search?advisor_ids=...&sub_fields=...&tags=...

GET /api/advisors/{advisor_id}/library?sub_field=...
- 浏览特定导师的特定研究领域库
```

## 7. 关键设计原理

| 特性 | 设计原理 | 好处 |
|------|--------|------|
| 按导师分库 | 每个导师独立库 | 隔离、可管理、易于访问控制 |
| 子领域分类 | 每个导师库内分类 | 细粒度检索、减少信息冗余 |
| 导师标记 | 核心/方法/争议等 | 导师的推荐信号被系统重视 |
| 多重过滤 | 可选过滤+权重 | 灵活满足不同查询需求 |
| 向量+元数据 | 混合检索 | 又快又准，支持多维查询 |
| 访问控制 | 基于关系 | 保护导师库隐私，支持多导师关系 |

这个设计的核心优势是：**让研究者能轻松在多个导师的专属文献库中检索和发现，同时导师能清晰标记和管理自己的库。**
